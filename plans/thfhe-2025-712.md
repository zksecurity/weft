# Modelling ePrint 2025/712 in Weft: which functionalities, and how far

Paper: Brakerski, Friedman, Marmor, Mutzari, Spiizer, Trieu, *Threshold FHE
with Efficient Asynchronous Decryption*, ePrint 2025/712 (revised
2025-10-16).  This note records what of it Weft can state and prove, what
belongs to the trusted base of a Weft development, what is out of scope by
design (DESIGN §1, report "Scope decisions"), and the functionalities and
library additions the modelable part needs.  It is a plan, not a record of
work done; nothing below exists in Lean yet.

## 1. What the paper contains

Setting: `N` parties, threshold `t`, up to `t` static malicious corruptions,
asynchronous reliable broadcast, BGV over `R_Q = ℤ_Q[x]/(xⁿ+1)`, plaintext modulus `p`.

| Component | Where | Content |
|---|---|---|
| Shamir over rings | §4, Thm 1, Lem 1–4, Cor 1 | Interpolation points `±xʲ` (an exceptional set), denominator-clearing factor `Δ`, `‖Δ·λ‖₁ ≤ 2^{3N/4}`, `‖λ‖₁ ≤ 2t` |
| `F_ThFHE` | §3.1, Functionality 1 | Setup with adversarial key bias `(δ, ε)`; decrypt after `t+1` requests, broadcast `pt` |
| Protocol 1 | §5, Thm 2 (correctness), Thm 3 (UC, statistical) | `ds_i = ct₁·sk_i + pΔe_i`, `e_i ← χ_D`, ZK proof per share; `pt = ct₀ − Σ λ_j ds_j mod p` |
| Protocol 2 | §6, Thm 4, Thm 5 (UC, computational) | Key switch to a "committed" ciphertext; TAHE-encrypted randomiser `E(u_ks)`; offline batch of encryptions of zero `ĉt_i` with randomiser `û_i` plus batched ZK; online: TAHE-decrypt `u + û`, decommit `ct + ĉt` in the clear, ZK proofs checked only on failure |
| `F^preprocess_ThFHE`, `F_TAHE` | App. E.8, Functionalities 2–3 | Preprocess records `(ct_F, u_F)` per session and hands `ct_F` to the adversary; decrypt reveals `u_ks + N_shift·u_F` with adversarial `N_shift`; TAHE with abort |
| PVSS | App. B, Protocol 3, Lem 5, Thm 9 | RLWE commitments `(a·s+e, a'·s+e')`, encrypted shares, ZK proofs |
| DKG | App. C, Protocols 4–6, Thms 6–8 | Consensus channel, post-determined participant sets, ROAST sessions, relinearisation and key-switching keys |
| Parameters | §7, App. D | Modulus growth `O(N)` vs `O(N log N)`, Sudler-product heuristics |

## 2. The cut: what Weft sees

Weft models programs over ideal functionalities and nothing below them: no
shares, no parties, no network (DESIGN §1).  Read the paper's threshold
decryption in that idiom and it is a **linear** program over an arithmetic
black box with one opening:

    decrypt([sk], ct):   [v] := ct₁ · [sk] + pΔ · [E]      -- E a fresh bounded noise share
                         v   := open [v]                   -- the one round
                         pt  := centred(ct₀ − v) mod p     -- in the clear

Everything the paper does *below* that line is the realisation of this
black box by Shamir sharing over `R_Q`: the interpolation points, `Δ`, the
Lagrange bounds, per-party noise, the adversary's choice of reconstruction
set, the ZK proofs, asynchrony and the `t+1` threshold.  That layer is
exactly what Weft puts in the trusted base (DESIGN §2.11: "the framework
proves the hybrid layer").  Everything *above* the line is a program, and
Weft can state its correctness, its cost and its privacy.

The privacy argument of Theorem 3 splits accordingly.  The opened value is
`v = ct₀ − pt + pΔ(E − e_ct)`; a simulator that knows `pt` and `ct` outputs
`ct₀ − pt + pΔE'` with a fresh `E'`.  The distance is that of a uniform
ball shifted by the ciphertext noise `e_ct`, at most `n·B/(2r_D+1)`.  The
paper's condition `r_D > n·2t·2^σ·r_E` carries an extra `2t`: it is Lemma 4,
the `ℓ₁` bound on the Lagrange coefficients, which belongs to the sharing
layer and is invisible above the line.  So Weft would state the ABB-level
bound and the trusted base owes the `2t`.

### What can be modelled, what cannot

| Paper item | In Weft | How |
|---|---|---|
| Decryption program (both protocols) | **yes** | `Prog` over `[Lin R, Reveal R, Noise R r]`, resp. `[Lin M, Reveal M, ZeroEnc]` |
| Thm 2 / Thm 4 correctness | **yes, perfect under `Pre`** | The no-wrap inequality is the precondition; the output equals `pt` on the whole support (decision 011) |
| Thm 3 privacy (noise flooding) | **yes, statistical** | `RealizationStat` with `ε = n·B/(2r+1)`; needs the flooding lemma (§4) |
| Thm 5 privacy | **partly** | Perfect realisation of a spec that *declares* `(u*, ĉt)`, as Functionality 2 does; that these hide `sk` is RLWE/AHE semantic security, prose only (scope decision) |
| Leakage over many decryptions | **yes, once the budget theorem exists** | `budget` of a caller doing `k` decryptions is `k·ε` (`Weft/Statistical.lean`, theorem not yet stated) |
| Rounds, communication | **yes** | Price lists parameterised by `N`; one reveal round; `O(N)` vs `O(1)` share size as two lists |
| Key switching, decomposition, decommit | **yes, as clear code** | Public ciphertexts and keys are `D.clear` values; the continuation is ordinary Lean |
| `F_ThFHE` setup with adversarial bias `(δ, ε)`; `N_shift`; abort in `F_TAHE` | **no** | Weft functionalities have no adversary port: a model is a fixed `PMF`, the adversary only observes |
| `t+1` requests before responding; asynchrony; participant sets | **no** | The black box erases the network; one program request is one decryption; the timed domain is synchronous rounds |
| Thm 1, Lem 1–4, Cor 1 (`Δ`, exceptional sets, norms) | **outside Weft** | Pure `ℤ[x]` algebra; formalisable in Lean on Mathlib as a separate development, but it is a fact about the protocol layer, not about a program |
| ZK proofs, PVSS, commitments, cheater identification | **no** | Malicious behaviour is below the black box; Weft realisations are in the ideal-functionality hybrid |
| DKG (Protocols 4–6), sessions, ROAST | **no** | Stateful, interactive, adversarially scheduled; stateless functionalities are a scope decision |
| Modulus growth with `N` | **as a parameter** | A price list may carry a modulus per `N`; the bound itself is Theorem 1 |
| Persistent hidden state across requests (`sid`, `ssid`, `τ`) | **as shares held by the caller** | `[sk]`, `[u_ks]`, `[û_τ]` are share operands or fresh responses; a two-operation spec replaces the stateful functionality |

## 3. Functionalities required

### 3.0 Prerequisite: the ring

Not a functionality, but the type every one below is instantiated at.

* `R n Q := Fin n → ZMod Q` with negacyclic multiplication, computable, so
  that small instances close by `decide +kernel` as the examples do.
  `Add`, `Sub`, `Mul`, `Zero`, `One` for `Lin`; the ring laws by transport
  from `AdjoinRoot (X^n + 1)` or by direct proof, only where a correctness
  proof needs them.  Mathlib's `AdjoinRoot` alone will not do: `Polynomial`
  is noncomputable, so nothing evaluates.
* `centred : ZMod Q → ℤ`, `‖·‖∞`, `‖·‖₁` on coefficients, and the two lemmas
  the correctness proofs use: *no wrap* (`‖x‖∞ < Q/2 → centred (x mod Q) = x`)
  and *extraction* (`centred (pt + p·e) mod p = pt` when `‖pt‖∞ < p/2` and
  no wrap).
* `Ball R r := {e : R // ‖e‖∞ ≤ r}` with `Fintype`, `DecidableEq`, `Nonempty`,
  the analogue of `{x : F // x ≠ 0}` in `RandNZ`.

Also `R n M` at the TAHE plaintext modulus `M`, and the clear embedding
`R n Q → R n M` by centred representatives.

### 3.1 `Noise R r` — a fresh bounded noise share (new, `Weft/Std/Random.lean`)

    get : [] → share R            model: uniform on `Ball R r`, nothing declared

The black-box rendering of "each party adds `pΔe_i`, `e_i ← χ_D`": the
*reconstructed* flooding noise is one fresh bounded share.  Same shape as
`RandNZ` (uniform on a subtype); worth a common `UniformOn (s : R → Prop)`
constructor with both as instances.  Priced `⟨0, 0⟩`: the noise is sampled
locally, like PRSS randomness.

Used by both protocols: as `χ_D` in Protocol 1 and as `χ̂_E` (the randomiser
mask `û`) in the share-only reading of Protocol 2.

### 3.2 `ThDec R p Δ` — the specification of Protocol 1 (new, example)

    dec : [share R, clear (R × R)] → clear R_p        model: `centred (ct₀ − ct₁·sk) mod p`, nothing declared
    Pre : ct is well formed under sk with noise ≤ B, and the no-wrap inequality holds

Deterministic, so `Functionality.ofEval`.  The clear response is in the
event by shape, which is what hands `pt` to the simulator; `ct` is a clear
operand and is in the event too (`Event.args`).  `Pre` mentions the share
`sk`: preconditions are on ideal requests, where a share is its value, so
"`ct₀ − ct₁·sk = pt + pΔe` with `‖e‖∞ ≤ B`" is a legitimate `Pre`, as
`x ≠ 0` is in `Examples/Inversion.lean`.

The program, over `[Lin R, Reveal R, Noise R r]`:

    thDec (sk : D.share R) (ct : D.clear (R × R)) : Prog fs.ops D (D.clear R_p) := do
      let e ← noise R r
      let t ← smul (Prod.snd <$> ct) sk           -- ct₁ · sk, free
      let f ← smul (pure (p * Δ)) e               -- pΔ · E, free
      let v ← reveal (← add t f)                  -- one round
      pure ((fun c v => centred (c.1 − v) mod p) <$> ct <*> v)

Theorems: `thDec_dist` (the run is "draw `E`, output `pt`, trace with the
opened `ct₀ − pt + pΔ(E − e)`"), correctness by the two ring lemmas, and
`thDecReal : RealizationStat (ThDec R p Δ) [Lin R, Reveal R, Noise R r]`
with `ε _ := n·B/(2r+1)`, whose `close` is the flooding lemma composed with
`PMF.statDist_map_le`.

### 3.3 The TAHE as a black box (reuse: `Lin M`, `Reveal M`)

Functionality 3 *is* an arithmetic black box without multiplication: `E(x)`
is `⟦x⟧`, `⊕` is `add`, `ct'₁ ⊙ E(u_ks)` is `smul` by a public ring element,
threshold decryption is `reveal`.  Nothing new is needed; the hybrid is
`[Lin (R n M), Reveal (R n M)]`.  The paper's "TAHE plaintext size at least
`N·2n·2^σ·Q`" becomes the no-wrap part of `Pre` at modulus `M`.  What does
not carry over is `F_TAHE`'s `continue/abort` with the corrupted set: Weft
has no abort.

### 3.4 `ZeroEnc R pk r̂` — the offline phase of Protocol 2 (new, example)

    get : [] → share M × clear (R × R)
    model: draw û ← Ball r̂, ê₀ ê₁ ← Ball r_E; return (⟦û⟧, (û·b + p·ê₀, û·a + p·ê₁)), nothing declared

The honest aggregate of the `t+1` published pairs `(ĉt_i, E(û_i))`: one
share of the randomiser and one public encryption of zero under it.  The
batching over `τ ∈ [B]` is `B` calls; one-time use of each `û_τ` is
structural (each `get` is fresh), which is the discipline §2.2 of the paper
warns about ("the same preprocess round used twice").  The ZK proofs that
tie `ĉt_i` to `E(û_i)` are what makes the *protocol* realise this
functionality; they are trusted base.

Its clear response depends on the secret `û` and is RLWE-hidden, not
information-theoretically hidden.  That is the one place Protocol 2 leaves
Weft's reach, and it decides how the spec must be written (§3.5).

### 3.5 `PreThDec` — the specification of Protocol 2 (new, example), in two readings

The program, over `[Lin M, Reveal M, ZeroEnc R pk r̂]`, with `u_ks` a share
operand (the DKG's `E(u_ks)`) and `ks`, `ct'` clear operands:

    preDec (uks : D.share M) (ks : D.clear KS) (ct' : D.clear (R × R)) : Prog fs.ops D (D.clear (Option R_p)) := do
      let (û, ĉt) ← zeroEnc                          -- offline output
      let ct := keySwitch <$> ks <*> ct'              -- clear
      let u  ← smul (lift ∘ Prod.snd <$> ct') uks     -- E(u) = ct'₁ ⊙ E(u_ks), free
      let w  ← add u û                                -- E(u) ⊕ E(û), free
      let u* ← reveal w                               -- one TAHE decryption: one round
      pure (decommit <$> ct <*> ĉt <*> u*)            -- clear: check ct + ĉt against u*, extract pt or fail

**Reading A, end to end, perfect, declared disclosure.**  Spec with
`cod := clear (Option R_p)` and `leak := M × (R × R)`: it returns the
decommit result and discloses `(u*, ĉt)` with the honest joint law.  This is
Functionality 2 minus `N_shift`: the paper's functionality also hands `ct_F`
to the adversary and reveals the masked randomiser.  The realisation is
perfect (the spec carries the coins), the proof is `simp only [weft]; rfl`
in the style of `randComb2Real`.  The statement is "the protocol reveals
nothing beyond `pt`, `u*` and `ĉt`"; that `(u*, ĉt)` reveal nothing about
`sk` is Theorem 5's computational content and stays in prose.

**Reading B, online phase only, statistical.**  Take the offline outputs as
operands, `dom := [share M, share M, clear KS, clear (R × R), clear (R × R)]`
for `(u_ks, û, ks, ct', ĉt)`, over `[Lin M, Reveal M]` alone; spec returns
`decommit (ct + ĉt) (u + û)` (deterministic in the ideal operands, so the
output marginal is exact) and discloses a *fresh* `û' ← Ball r̂` independent
of everything.  The simulator replays `reveal û'`; the real view has
`reveal (u + û)`; the flooding lemma bounds the distance by `n·‖u‖∞/(2r̂+1)`
under `Pre : ‖u_ks‖∞ ≤ r_E`.  This is the share-level content of Theorem 5:
the one TAHE opening is noise.

Both readings are worth having; B is the theorem, A is the shape a caller
composes with.

### 3.6 `KeyGen R χ` — optional, trusted base

    keygen : [clear R] → share R × clear R        model: sk ← χ, e ← χ; return (⟦sk⟧, a·sk + pΔe)

Only so that an end-to-end caller (`keygen`, then decryptions) can be
written and costed.  Its clear output is RLWE-hidden, so a caller's spec
must declare `pk`, which `F_ThFHE` does anyway (it sends `pk` to all).  The
adversarial bias `(δ, ε)` of Functionality 1 is not expressible.  Its
realisation by Protocol 5 is out of scope; `Realization.incl` is all Weft
says about it.

### 3.7 Price lists

    native N   := [(Lin R).priced ⟨0,0⟩, (Reveal R).priced ⟨1, N⟩, (Noise R r).priced ⟨0,0⟩]
    optimised N := [(Lin M).priced ⟨0,0⟩, (Reveal M).priced ⟨1, N⟩, (ZeroEnc …).priced ⟨0,0⟩]   -- offline outputs precomputed
    optimisedOnline N := … (ZeroEnc …).priced ⟨1, N⟩                                       -- offline round paid online

Delay 1 for both decryptions; communication `N` units per opening, with the
unit's size (a ring element of `R_Q` growing with `N`, or a constant-size
class-group ciphertext) a parameter of the list, as `twoField` prices per
field.  Both are closed instances by `decide +kernel` at small `n, Q`, and
`commOn (native N) thDec = N` for all `N` should follow by `simp` since the
program is straight-line.

## 4. Library additions the plan needs

1. **The flooding lemma** (`Weft/PMF.lean`), the statistical sibling of the
   mask lemma `uniform_map_equiv`:

       r + ‖e‖∞ < Q/2 →
       statDist (uniform (Ball r)) ((uniform (Ball r)).map (· + e)) ≤ ‖e‖₁ / (2r + 1)

   (the hypothesis keeps the shifted ball from wrapping modulo `Q`),
   coordinatewise (`Ball` is a product of intervals), then
   `PMF.statDist_map_le` for the affine map to the opened value.  This is
   the one new probabilistic fact; decision 009 already names "masking a
   bounded value by a longer random one, `ε = 2^{−κ}`" as the first
   statistical case, and it is this lemma.
2. **The budget theorem** (`Weft/Statistical.lean`, listed in the README as
   not yet proved): `handle_realizes` up to `min 1 (budget …)`.  It is what
   turns `thDecReal`'s per-request `ε` into "`k` decryptions with the same
   key leak at most `k·ε`", the paper's own motivation for flooding.
3. **`UniformOn`**, a constructor for "uniform on a decidable subset",
   generalising `RandNZ`, with `Noise` as its second instance.
4. **The ring** of §3.0 with its norm lemmas, under `Weft/Std/` if it is to
   be shared or under `Examples/ThFHE/` if not.
5. Nothing in `Prog`, `Model`, `Realization` or the timed layer needs to
   change: the programs are straight-line, the specs are one operation
   each, the disclosures are the existing joint-step mechanism.

## 6. What this exercise says about Weft

* The paper's protocols are *linear* programs with one opening each, which
  is why one round suffices and why no `Mult` appears; the black box that
  hosts them is `[Lin, Reveal]` plus a noise source.
* Noise flooding is the first client for the statistical layer that is not
  a rejection or a `randNZ` workaround, and it needs exactly the lemma
  decision 009 anticipated.
* Two things the paper's functionalities have and Weft's do not: an
  adversary port (`bias`, `N_shift`, `continue/abort`) and persistent state
  across requests (`sid`, `ssid`).  The second is bypassed by passing shares
  explicitly; the first has no workaround and marks the boundary.  Both are
  recorded scope decisions, and this paper does not argue for changing
  them: the adversary's influence here is on the *protocol* layer's
  realisation of the black box, which is where Weft already places it.
